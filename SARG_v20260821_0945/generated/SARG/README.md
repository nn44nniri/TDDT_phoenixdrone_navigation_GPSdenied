# Generated SARG dataset — FMI-only strict mode

The authoritative mission extent, Origin and Destination are read from region_v1.geojson in WGS 84. CRP clusters and every route point are spatially validated against that region. Each record and route point includes its CRP code, time window and climate parameters. The canonical sarg_records.csv summary also carries the complete WingMPET energy/safety reference, MESA-NAV error/uncertainty reference, and separate wing_confidence/mesa_confidence/record_confidence fields. Unavailable values for NOT_TRIGGERED or invalid records use -9999. Coordinate semantics are explicit: WGS84 uses *_lon_deg/*_lat_deg, the projected map CRS uses *_x_m/*_y_m, the local frame is ENU and vertical coordinates are MSL. `region_crs` is no longer written to canonical records. The canonical lookup key is (regime_id, phase_id, crp_id); `sarg_lookup_index.csv` provides the compact Regime×CRP-local×Phase edge index. If a regime is not yet selected, callers must request all candidates for the current phase/stage and CRP rather than allowing SARG to infer a regime. See `scenario_climate_contexts.csv` for the explicit scenario×CRP context table.

All flight, navigation, safety, energy and trajectory state calculations are outputs of native operations in `WingMPET.fmu` and `MESA_NAV.fmu`. Python performs only data adaptation, scheduling, rejection/retry, aggregation and serialization. There is no deterministic/reference-envelope fallback. See `metadata.json` and `fmi_execution_trace.csv`.
